Running the agency on Claude agents

An operating plan for @riyadhasan.official

Draft 1  ·  28 October 2026  ·  For internal discussion

1. Why this document exists

Right now most of the work behind the account is done by hand. Someone reads every DM, checks the channel, forwards the good ones to Saheb bhai on WhatsApp, chases payments and makes the next reel. That works at around $2,000 a month. It won't work at $100,000, and not because the team is slow. There just aren't enough hours in the day.

This plan covers how we move the repeatable parts of that work onto a team of AI agents built on Claude: what each agent does, where people stay in charge, what it costs, and the order we build it in.

One decision up front: everything runs on Claude. No Grok bot, and no mix of AI tools from three different companies. One platform means one bill, one set of logs, one place to look when something breaks, and agents that all work from the same knowledge about the business.

What the plan doesn't do is just as important. It doesn't replace Saheb bhai on sales, and no agent will move money, sign anything or file anything legal on its own. Section 6 spells out exactly where that line is.

3. What we'll build it with

Everything AI-related sits on Anthropic's Claude platform. In plain terms:

Claude models (the brain). Claude Opus 5.5 is the main model. It handles judgment calls best, like reading a messy DM thread or a strike notice. For high-volume, simple steps we'll later test Claude Haiku 5.5, which costs a small fraction of Opus. We only switch if it gives the same answers on our real conversations.

Claude Managed Agents (where the agents live). Anthropic runs each agent and gives it its own workspace where it can read files, run code and use tools. The parts we actually need:

  • Each agent's instructions are saved with a version number. If a change makes an agent worse, we roll back to the last good version.
  • Agents can run on a schedule, for example the daily report every evening at 10 pm.
  • A shared memory holds prices, FAQ, rules and tone of voice. Every agent reads from it, and every change is recorded.
  • API keys and tokens live in a vault, not inside the instructions. Agents can use them without ever seeing them.
  • Each run can have a hard dollar cap, so a stuck agent can't burn money overnight.
  • Work can be graded against a written checklist by a separate checker, and sent back until it passes. That's how the quality check agent will work.

Managed Agents is still labelled beta by Anthropic. We'll keep our own code thin, so if we ever need to move to the plain Claude API, it's a few days of work, not a rebuild.

Claude Code (how we build it). The small amount of connecting code (receiving Instagram messages, writing to the sheet, sending WhatsApp messages) gets written and maintained with Claude Code.

Claude projects on claude.ai (for the people). Saheb bhai and the team get a Claude project loaded with the same business knowledge, for one-off things like drafting a proposal or working out how to answer an unusual question.

What isn't Claude but we still need. These aren't AI tools. They're the pipes that carry messages and data:

  • Meta's official Instagram API, to read and answer DMs and to publish posts. It needs a professional Instagram account, a Meta app, and Meta's app review.
  • WhatsApp Business Platform (Cloud API), for lead cards and reports.
  • YouTube Data API, to look up a channel's public subscriber count. With the owner's permission, the YouTube Analytics API for revenue numbers.
  • Google Sheets as our customer list (CRM) to start with. Everyone can open it and fix things by hand.
  • A small server, a few dollars a month, that receives messages from Instagram and WhatsApp and passes them to the right agent.

On Instagram specifically: we won't use any tool that logs into the account with the password and pretends to be a person. Those tools are the most common way accounts get restricted, and this account is the entire sales funnel. Official API only.

DM handling agent

This is where the money starts, so it's the first agent we build and the one we test hardest.

When a DM comes in, Instagram sends it to our server, which hands it to the DM agent together with the conversation so far. The agent then:

  1. Replies in whatever language the person used: Bangla, Hindi, English, or a mix of them.
  2. Asks for the channel link if it doesn't have one yet.
  3. Looks up the subscriber count through the YouTube API. Two catches here. YouTube rounds public counts (a channel with 102,345 subscribers shows as 102,000), and some channels hide the count completely. If it's hidden or close to the line, the agent asks for a YouTube Studio screenshot.
  4. Checks monetization. That isn't public, so the agent asks for a screenshot of the Earn page in YouTube Studio and reads it, since Claude can read images. Screenshots can be edited, so this is only a first filter. The real confirmation happens at onboarding, when we get proper access to the channel.
  5. Decides: qualified, not yet (for example 80k to 99k subscribers, or not monetized yet), or not a fit.

For a qualified lead, the agent adds a row to the Leads sheet and sends Saheb bhai a lead card on WhatsApp. The card has the name, channel link, subscriber count, niche, language, what they want (copyright work or strike help), the monetization screenshot, and a two-line summary of the chat. The YouTuber gets Saheb bhai's WhatsApp link with a short note on what happens next. Our target is a lead card within five minutes of the DM, day or night.

"Not yet" leads go on a separate list. A channel at 85k today could be a customer in a few months, and the Manager agent will flag them for a check-in later.

When it hands over to a person: if someone is upset or confused, asks detailed money questions (rates, guarantees, contracts), mentions a legal problem, asks for a human, or says something the agent isn't sure how to handle. The agent tells them someone from the team will reply and pings the team on WhatsApp. Instagram's rules only allow automated replies within 24 hours of the person's last message, so handovers have to be picked up the same day.

What it never does: promise an income figure, use the word "guaranteed", ask for a password or OTP, or argue with anyone.

One extra that helps growth is comment-to-DM. When someone comments a keyword like "INFO" on a reel, Instagram lets the business send one private message in reply to that comment. The social media agent sends that first message, and if the person answers, the DM agent takes over. It's a cheap way to turn reel views into conversations.

Onboarding agent

This starts when Saheb bhai marks a deal as won. To keep it simple, Saheb bhai just replies to the lead card on WhatsApp with "WON", or "LOST" plus a reason. Our server picks that up and updates the sheet, so nobody has to open a spreadsheet in the middle of a sales day.

From there the agent sends the welcome message and the agreement. The agreement template is fixed (revenue share terms with 40% to the owner, payment dates, what we do and don't do), and the agent only fills in names and details. A person checks it before it goes out.

Next it sets up channel access the right way. The owner adds our account through YouTube Studio's channel permissions (Settings, then Permissions). Nobody shares a password, ever. This protects the owner as much as us, and clients notice that.

It also collects what the content team needs (niche, audience, best-performing past videos, topics to avoid), creates the client's row in the Clients sheet and a folder for files, and tells the Research agent to start. On day 3 and day 14 it sends a short "how's it going" message.

Finance agent

Probably the least exciting agent, and the one that saves the most headaches.

  • Once a client authorizes it, it pulls estimated revenue from the YouTube Analytics API, so nobody types numbers off screenshots.
  • It works out the split per client per month (40% to the channel owner, the rest to us) and any strike fees owed.
  • It prepares invoices and payment reminders, and logs payments as they come in.
  • It tracks our own costs too, including the Claude bill, so we always know the real margin.
  • On the 1st of every month, the owner gets a one-page profit and loss summary.

It never sends money and never changes an invoice once it's sent. A person approves every invoice and every payout.

Strike desk agent

When a client reports a strike, the agent collects the details: which video, what kind of strike (copyright strike, Community Guidelines strike, or just a Content ID claim, which isn't a strike at all), who filed it, and when. Deadlines go into the Strikes sheet. Strikes expire after 90 days, and three active strikes means YouTube terminates the channel, so the count matters more than anything else.

Then it lays out the honest options: wait it out, ask the claimant to retract, appeal (for Community Guidelines strikes), or file a counter notification (for copyright strikes). It drafts whatever is needed and sends the fee request (₹5,000 or ₹10,000) through the Finance agent.

One hard rule. A counter notification is a legal statement, made under penalty of perjury, and the claimant can take it to court. The agent drafts it, a person checks that the client really owns the rights, and the client submits it. The agent never promises that a strike will be removed. That's what "no false promises" looks like in practice.

The content line: Research, Script, Design, Quality check, Social media

These five work as one assembly line, both for our own Instagram and for client channels.

Research looks once a week at what's working in each client's niche, what's trending and what competitors posted, and writes a short topic list with a reason next to each topic. It uses web search, and it keeps a running file of what has worked for us before.

Script turns approved topics into scripts. For our Instagram that means reels with a hook in the first two seconds, revenue proof stories and client results (with permission). For client channels it means video scripts. It writes in the brand's tone, taken from the shared memory.

Design needs an honest note first: Claude doesn't generate photos the way image generators do. What it does well is layout. It builds thumbnails, story frames and carousels from our own templates, fonts and photos, and exports them as images. It can also do simple video work in its workspace, like adding captions or cutting clips. Heavy editing stays with a human editor for now.

Quality check is the gate. Nothing goes out without passing it. It checks every piece against a written checklist: facts and numbers, spelling, brand tone, Instagram and YouTube rules, and rights (is every clip, song and image ours, licensed, or allowed to be reused?). It sends work back to Script or Design with notes until it passes. It also reads a random 10% of DM conversations every week and reports anything the DM agent got wrong. That's how the DM agent gets better over time.

Revenue proof gets extra care. It has to be a real screenshot from a real channel, used with the client's permission and with personal details blurred. The agents never create, edit or "improve" revenue numbers. If we want to be the agency that doesn't lie, our proof has to be the most boring, checkable thing on the page.

Social media publishes approved posts and reels through the Instagram API according to the content calendar, writes captions, runs comment-to-DM, and reports which posts brought in DMs, not just likes. Revenue proof posts need the owner's OK before they go live.

Manager agent

Every evening it reads the sheets and logs and sends the owner a short WhatsApp report: DMs that day, how many qualified, how many went to Saheb bhai, deals won, content published, content waiting for approval. Most importantly, it lists anything stuck, like a lead nobody followed up within 24 hours, an unpaid invoice, or a strike deadline this week. On Monday mornings it sends the weekly version with funnel numbers and costs. It nudges people politely. It doesn't make decisions.

On top of that, every agent follows the same short list of rules, written into its instructions:

  1. No income promises, and never the word "guaranteed".
  2. Never ask for passwords, OTPs or recovery codes. Channel access only through YouTube Studio permissions.
  3. Never create or edit revenue proof.
  4. Nothing gets uploaded without passing the rights check.
  5. No legal filings and no moving money.
  6. When unsure, hand over to a person and say so honestly.
  7. Every run has a spend cap.

7. Where the data lives

Google Sheet (our CRM) with five tabs: Leads, Clients, Content calendar, Strikes and Money. It's simple on purpose. If we outgrow it, say a few thousand new rows a month, we move to a proper database and the agents won't care.

Shared memory in Claude holds prices, FAQ, qualifying rules, tone of voice, examples of good DM replies and lessons learned. Every change is versioned, so we can always see when the price list changed and roll it back if needed.

Vault holds the Instagram, WhatsApp, Google and YouTube tokens. They never go into the shared memory and never into a chat.

Client data such as revenue numbers and contact details is only visible to the agents that need it. Finance sees money. The DM agent doesn't.

9. From $2,000 to $100,000: what the numbers say

Agents make us faster and let us handle ten times the conversations without hiring ten more people. But they don't create demand on their own. To get to $100k a month, four things have to move: how many DMs we get, how many qualify, how many close, and how much we earn per active channel each month (plus how long clients stay with us).

The number that decides most of it is our average monthly income per active channel. Here is how many active channels $100k takes at different levels:

Our average income per channel per monthActive channels needed
$200500
$400250
$800125
$1,500about 67

Working backwards from that: to add 20 new channels a month at a 30% close rate, Saheb bhai needs about 67 qualified leads a month. If 15% of DMs qualify, that's around 450 DM conversations a month. Those percentages are placeholders. After the first month the Manager agent gives us the real ones, and this section gets rewritten with them.

Where the agents actually move the numbers:

  • No DM waits until the next afternoon. Replies go out in a minute, even at 2 am, and fast replies close more often.
  • Nothing falls through the cracks. Every "not yet" channel gets a follow-up when it crosses 100k.
  • Saheb bhai only talks to qualified people, with a summary already in hand, which means more closes per hour.
  • More content gets made, and it's judged by the DMs it brings in rather than by likes.
  • Clients who are paid correctly and on time stay longer. In a revenue-share business, losing clients quietly hurts more than not finding new ones.

And where they won't help: if income per channel is low, or channels keep getting terminated, no amount of DM speed fixes that. Strike forward is useful extra income, but at ₹5,000 a strike it would take roughly 1,700 strikes a month to reach $100k. It's an add-on, not the engine.

11. Risks and how we handle them

The Instagram account gets restricted. This account is the whole funnel. We use the official API only, never send cold DMs (the API doesn't allow them anyway), avoid spammy repeat messages, and make sure handovers are answered within 24 hours.

Copyright and channel safety. This document doesn't go into how copyright work is done, and it doesn't need to. But one rule goes into the system either way: the quality check agent won't pass any upload unless the footage, music and images are owned, licensed, or clearly allowed for reuse. Uploading other people's videos is the fastest way to collect strikes, lose monetization under YouTube's reused content policy, and get a channel terminated after three strikes in 90 days. Every terminated client channel ends a revenue share, so this is about protecting the business, not just following rules.

The DM agent says something wrong. The shared memory has exact prices and rules, the agent starts in draft mode, the quality check agent reads 10% of chats every week, and the agent hands over whenever it isn't sure.

Fake screenshots. A screenshot is only the first filter. Proper channel access during onboarding is the real check.

Client data leaks. Channel permissions instead of passwords, tokens in the vault, and each agent only sees the data it needs.

Too much depends on one person or one account. Lead cards and the sheet make Saheb bhai's pipeline visible, so a second salesperson can pick it up if needed. Over time we should also build a second channel of our own, so one Instagram account isn't the only door in.

Costs creep up. Spend caps per run, a monthly limit, and the Claude bill in every weekly report.
